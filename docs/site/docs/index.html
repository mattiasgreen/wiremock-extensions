WireMock Extensions Suite Guide

Comprehensive reference documentation, API routes, Gradle/Maven coordinates, and design patterns for production-grade API simulation on the JVM and Standalone.

1. Quickstart & Subproject Topology

The suite is built for JDK 21+ and WireMock Standalone 3.x. You can include all extensions via the meta-bundle or pick individual modules for lightweight containerized testing.

Extension Subproject Responsibility Primary Admin Route / SPI Hook
wiremock-extension-bundle Meta-packaging aggregating all extensions with Java SPI auto-discovery. Includes all endpoints + local dev runner
wiremock-extension-ui Embedded Vanilla JS web console with stubs viewer, scenario DAG, and tester. /__admin/ui/ (Static assets)
wiremock-extension-stateful In-memory dynamic AST simulation with correlation-id session isolation. /__admin/stateful/models + Filter
wiremock-extension-tcp-netem In-process L4 network emulation & fault injection (Toxiproxy in Java 21). /__admin/netem/proxies (Port 8081)
wiremock-extension-openapi OAS 3.0/3.1 parser, mock data synthesizer, and live proxy recorder. /__admin/openapi/import
wiremock-extension-casual In-process Netty Casual (XATMI) domain gateway, stub-driven dynamic proxying, 2PC stickiness, and synthetic XA voting. /__admin/casual/config (TCP :7772)
wiremock-extension-otel In-process request counters, latency histograms, and W3C tracing spans. /__admin/metrics/prometheus
wiremock-extension-json-logging Single-line structured JSON logs with MDC header propagation. RequestFilterV2, ServeEventListener

2. Standalone, Docker & JUnit 5 Execution

Standalone CLI Execution

WireMock discovers extensions via standard Java SPI (java.util.ServiceLoader). Place both JARs on the classpath:

# Download WireMock Standalone & the Extension Bundle:
java -cp "wiremock-extension-bundle-1.6.0.jar:wiremock-standalone-3.12.1.jar" \
  com.github.tomakehurst.wiremock.standalone.WireMockServerRunner \
  --port 8080 --verbose

Production Dockerfile Reference

Assemble a minimal alpine container running the unified server:

FROM eclipse-temurin:21-jre-alpine
WORKDIR /wiremock

ARG WIREMOCK_VERSION=3.12.1
ARG BUNDLE_VERSION=1.6.0

RUN wget -q "https://repo1.maven.org/maven2/org/wiremock/wiremock-standalone/${WIREMOCK_VERSION}/wiremock-standalone-${WIREMOCK_VERSION}.jar" -O wiremock.jar \
 && wget -q "https://repo1.maven.org/maven2/io/github/mattiasgreen/wiremock-extension-bundle/${BUNDLE_VERSION}/wiremock-extension-bundle-${BUNDLE_VERSION}.jar" -O bundle.jar

EXPOSE 8080 8081 7772
ENTRYPOINT ["java", "-cp", "wiremock.jar:bundle.jar", "com.github.tomakehurst.wiremock.standalone.WireMockServerRunner", "--port", "8080"]

JUnit 5 Test Embedding

Standard JUnit 5 WireMock tests automatically discover and activate all extensions via Java SPI. Simply add the bundle to your test dependencies: 

// Gradle build.gradle
testImplementation 'io.github.mattiasgreen:wiremock-extension-bundle:1.6.0'

// In your test class:
@WireMockTest(httpPort = 8080)
class OrderServiceIntegrationTest {
    @Test
    void shouldProcessOrdersWithObservability() {
        // All extensions (Web UI, NetEm L4, Prometheus, JSON logs) run in-process
    }
}

3. Extension Module Reference

🖥️ WireMock Console (`wiremock-extension-ui`)

An embedded, zero-dependency web dashboard served natively under http://localhost:8080/__admin/ui/.

  • Stubs Explorer & Dual-Mode Editor: Fuzzy search by URL path, HTTP method, stub name, or tag. Create and edit stubs using either the structured Form Mode or the full-featured Raw JSON Mode with live roundtrip synchronization, syntax validation, and formatted JSON indentation.
  • Scenario DAG Visualizer: Renders complex multi-step scenario transitions as interactive directed acyclic graphs with reset controls.
  • Request Journal: Inspect captured requests with payload diffs, match explanations, inline Base64 JSON decoding ([Raw] / [Decoded] toggles), and one-click cURL export.
  • Snapshot Recording: Snapshot authentic proxied requests directly into offline static stubs with exact request body matching (equalToJson, equalTo, binaryEqualTo) to prevent collisions.
  • HTTP Tester: Execute test requests against stubs with real-time response rendering and execution timers.

Headless Console Proxy: The UI can also run in decoupled standalone mode (java WireMockConsoleProxy.java) to control remote WireMock instances in staging clusters without installing anything on the remote host.

⚡ Stateful AST Engine (`wiremock-extension-stateful`)

Solves parallel test collision pitfalls. Standard WireMock scenarios mutate global singleton state. When tests execute concurrently in parallel CI workers, they overwrite each other's scenario states.

wiremock-extension-stateful introduces an in-memory Abstract Syntax Tree (AST) evaluator with X-Correlation-Id session partitioning. Each test worker gets its own isolated state world. 

// Define model with type-safe Java DSL:
StateModel model = StateModel.named("CaseManagement")
    .initialState("DRAFT")
    .transition("SUBMIT", "DRAFT", "PENDING_REVIEW")
    .transition("APPROVE", "PENDING_REVIEW", "APPROVED")
    .invariant("NoPendingTasks", expr -> expr.collection("tasks").noneMatch(t -> t.is("PENDING")));

🌪️ TCP NetEm Chaos (`wiremock-extension-tcp-netem`)

In-process Layer 4 network impairment engine inspired by Shopify Toxiproxy, re-implemented natively using modern Java 21 Virtual Threads (Thread.ofVirtual()).

Exposes Toxiproxy v2-compatible REST routes on Port 8080 under /__admin/netem/proxies, routing traffic through Port 8081 down to Port 8080 with zero external C or Go containers.

  • latency: Inject delay with configurable normal-distribution jitter.
  • bandwidth: Throttle data rate in kilobytes per second.
  • slow_close: Delay socket FIN packet on teardown.
  • timeout: Black hole socket stream (hangs until client timeout).
  • reset_peer: Immediate TCP RST packet injection via Socket.setSoLinger(true, 0).
  • slicer: Fragment application packets into micro-chunks.
  • limit_data: Closes connection after N bytes transferred.

📑 OpenAPI Ingestion (`wiremock-extension-openapi`)

Ingest OpenAPI 3.0 / 3.1 specifications in JSON or YAML via POST /__admin/openapi/import. Synthesizes realistic format-aware responses (valid UUIDs, RFC-3339 timestamps, realistic emails, postal codes).

Supports Live Proxy Recording: forwards unmatched calls to an upstream API, logs traffic into the Request Journal, and lets you snapshot recorded sessions into offline stubs with one click.

🏛️ Casual Domain Gateway & 2PC Simulation (`wiremock-extension-casual`)

An in-process Layer 7 Tuxedo / Casual domain gateway on raw TCP (Port 7772) built on Netty. Enables end-to-end integration testing of distributed XATMI RPCs and Two-Phase Commit (2PC) transactions without heavy C++ domain brokers or JEE application servers.

  • Stub-Driven Dynamic Proxying: Declare dynamic proxy routes in standard WireMock proxy stubs where targetBaseUrl points to casual://<host>:<port>. Probes stubs in-memory with microsecond latency and forwards natively socket-to-socket over TCP.
  • Multi-Upstream 2PC / XA Stickiness: Tracks upstream connection enlistment per transaction identifier (Xid). Transparently routes PREPARE, COMMIT, and ROLLBACK frames across disparate remote domains.
  • Human-Readable Buffer Mediation: Automatically converts Fielded buffers (.FIELDED / CFIELD/) to/from structured JSON via FieldedTypeBuffer, strips/restores CSTRING/ null terminators, and records JSON text directly in the Request Journal.
  • Synthetic XA Participant: When decoupled from upstream servers or running offline, acts as a synthetic XA Resource Manager, automatically voting XA_OK (or simulating chaos via XAER_RMERR) to complete client commit loops.
// 1. Configure dynamic Casual proxy route in Java:
wireMock.stubFor(post(urlMatching("/__casual/services/.*"))
    .withName("Billing Service Proxy")
    .atPriority(10)
    .withMetadata(Map.of(
        "mode", "proxy",
        "targetBaseUrl", "casual://billing-upstream.corp:7771"))
    .willReturn(aResponse().withStatus(200)));

// 2. Or import via JSON Admin API (e.g. StandaloneDevServer):
POST http://localhost:8080/__admin/mappings
{
  "name": "Billing Service Proxy",
  "priority": 10,
  "request": { "method": "POST", "urlPattern": "/__casual/services/.*" },
  "response": { "status": 200 },
  "metadata": {
    "mode": "proxy",
    "protocol": "casual",
    "targetBaseUrl": "casual://billing-upstream.corp:7771"
  }
}

📊 OpenTelemetry & Metrics (`wiremock-extension-otel`)

Production observability for WireMock. Records request counts, response codes, and latency histograms:

  • Scrape route: GET /__admin/metrics/prometheus directly scrapeable by Prometheus / Grafana Agent.
  • Distributed Tracing: Extracts W3C traceparent headers, creates in-process SERVER spans, and correlates log events.
  • Optional OTLP Export: Ships spans via gRPC / HTTP to Jaeger, Tempo, or Datadog.

Progressive Simulation Walkthrough Tour

Watch how a real-world multi-protocol system (combining HTTP REST and binary Casual XATMI 2PC transactions) progresses from live upstream proxy recording to 100% offline simulation without touching a single line of client test code.

Simulation Lifecycle Breakdown:

  1. Live Proxy Mode: WireMock intercepts HTTP (CRM & Case APIs) and Casual TCP (2PC Billing) routes, passing traffic through to live backend services.
  2. Customer Journey Execution: The Customer Portal UI submits an application (creating cases, checking KYC) and confirms purchase with an XA-distributed billing charge.
  3. Unified Journal Observability: The WireMock Console UI displays both HTTP REST (200 OK) and protocol-native CASUAL (OK) frames side by side in the request journal.
  4. 1-Click Harvesting & Mode Switch: Traffic is snapshotted into deterministic stubs, and project groups are switched from LIVE PROXY to STUBS MODE.
  5. Upstream Severing & Offline Replay: The upstream backend is completely terminated. Replaying the identical application and purchase journey succeeds 100% from local stubs with local 2PC transaction synthesis.

4. Key Architectural Use Cases

Flake-Free Parallel CI Pipelines

By passing X-Correlation-Id: ${testRunId} on all HTTP requests, 50 parallel test runners can mutate stateful workflows against a single shared WireMock server without race conditions or state collisions.

Offline API Flight Mode

Import your service's OpenAPI spec in Live Proxy mode, exercise your regression suite once against staging, click Snapshot Traffic, and flip to Stubs Mode to run completely detached from the network.

Mobile Resiliency & Chaos Drills

Use TCP NetEm to simulate realistic 3G tunnel dropouts, erratic latency jitter, and abrupt TCP reset disconnects right before checkout requests complete to test retry loops.

Air-Gapped Compliance Mocking

100% on-premises with zero cloud callbacks, zero external CDN links, and zero telemetry beacons. Meets the highest compliance criteria in banking, healthcare, and defense.

5. Architecture & Zero-Sprawl SPI Design

Unified In-Process Control Plane

Standard enterprise mocking setups require spinning up a fleet of disparate containers: WireMock for L7 HTTP stubs, Shopify Toxiproxy for network impairment, a separate UI dashboard service, and local Prometheus exporters. This creates container sprawl, port conflicts, high CI memory footprints, and slow pipeline bootstrap times.

wiremock-extensions consolidates all simulation engines into an in-process, dual-ingress JVM architecture:

  • Port 8080 (WireMock Core & Admin Plane): Serves Admin API endpoints (/__admin/...), the embedded Vanilla JS Console (/__admin/ui/), Prometheus scrape route (/__admin/metrics/prometheus), and OpenAPI ingestion (/__admin/openapi/import).
  • Port 8081 (NetEm Virtual Thread Ingress): Transparent Layer 4 TCP proxy executing in the same JVM process, streaming directly to Port 8080 while injecting bandwidth throttling, socket slicing, or TCP resets on demand.

6. Zero-NPM & Web Standards Philosophy

Pure Vanilla ES Modules Without Bundlers

The embedded web console (wiremock-extension-ui) is built entirely with modern browser-native ES Modules (import / export), standard CSS variables, and HTML templates:

  • Zero NPM Dependencies: No package.json, no node_modules, and zero supply-chain vulnerability risks.
  • Zero Bundlers: No Webpack, Vite, Rollup, or Babel build steps required. Changes in src/main/resources/ui/ reload instantly in the browser.
  • Air-Gapped & CDN-Free: 100% of fonts, icons, styles, and scripts are embedded directly inside the JAR, guaranteeing reliable offline and air-gapped operation.
